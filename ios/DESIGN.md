# Concise English: clean-room design

Concise English is an independent iOS dictionary and thesaurus. It was designed
from general dictionary-app conventions, not from another product's code, data
or assets.

**About the reference APK.** The Android reference (`Concise.apkm`) was never
unpacked, decompiled, modified or copied into this repository, and nothing in
this app comes from it: no source, layouts, strings, icons, artwork, audio or
dictionary content. Anything specific to that app's behaviour that can only be
learned by using it is marked **needs black-box observation** below. To fill
those gaps, use the reference app on an Android device and write down what you
see, then change this design from those notes.

## B. Navigation map

```
TabView
├─ Search ── NavigationStack
│   ├─ Home (query empty) ──► Entry
│   ├─ Suggestions list ────► Entry
│   └─ Entry ──(synonym / related word chip)──► Entry ──► …
├─ Favourites ── NavigationStack ──► Entry ──► …
├─ History ── NavigationStack ──► Entry ──► …
└─ Settings ── NavigationStack ──► Sources and licences
```

Each tab has its own stack, so going from word to word builds a back history
that the standard back button and swipe-back gesture unwind.

Needs black-box observation: whether the reference app uses a drawer, tabs or a
single stack, and how its back stack behaves after following a cross-reference.

## D. Offline data requirements

All lookups read from one read-only SQLite file bundled with the app,
`ConciseEnglish/Resources/dictionary.sqlite` (about 44 MB). It is generated by
`Tools/build_dictionary.py` from:

* **Open English WordNet 2024** (CC BY 4.0): definitions, examples, senses,
  synonyms, antonyms, relations, irregular forms, some IPA.
* **CMU Pronouncing Dictionary** (BSD-2-Clause): fallback US IPA.

Tables: `word`, `entry` (per part of speech, with IPA), `sense`, `synset`
(definition and examples), `sense_relation`, `synset_relation`, `form`.

**How to swap in licensed data later.** The database file is the only boundary.
Generate a file with the same schema from any licensed source and replace the
bundled file. No Swift changes are needed unless new fields (for example
etymology) are added.

User data (history and favourites) is a small JSON file in Application Support.
Preferences are stored in `UserDefaults`.

The app makes no network calls. Speech uses voices installed on the iPhone. CI
fails the build if network APIs or URLs appear in the app code.

## E. State and interaction model

* `DictionaryStore` (an observable model) owns the database and exposes
  `suggestions`, `lookup`, `spellingAlternatives`, `wordOfTheDay` and
  `randomWord`. These are pure reads with deterministic results.
* `Library` (observable) holds history and favourites and saves on every
  change.
* `Pronouncer` wraps speech and audio-session ducking.
* Views hold only UI state: the query, navigation path, Dictionary/Thesaurus
  mode, and the expanded/collapsed state of long entries.
* Search: typing triggers a 60 ms debounced suggestion query (cancelled when the
  query changes). Return opens the typed term, which resolves to the exact word,
  then an irregular form, then the best suffix-rule match, and otherwise shows
  "not found" with alternatives.
* Opening an entry records it in History and, if enabled, speaks it.

## F. iOS implementation plan

1. Data pipeline: Python script producing the SQLite file. Done.
2. Data layer: SQLite wrapper, store, lemmatizer, library, speech. Done.
3. Screens: search/home, entry (dictionary and thesaurus), favourites,
   history, settings, licences. Done.
4. Project: Xcode project (iOS 17+, no third-party dependencies) and unit
   tests for every lookup flow and for persistence. Done.
5. CI: GitHub Actions builds and runs the tests on an iOS simulator, plus the
   offline guard. Done.
6. On-device check in Airplane Mode (see `README.md`). For you to run on your
   iPhone.
7. Next, once there are black-box notes on the reference app: adjust the layout
   and flows, and add browse A–Z, definition search or widgets if wanted.
